Research and limits

What this project builds on, how the rules work, and what the tool cannot do.

References

  • Main methodology paper: Ding et al., "Vulnerability Detection with Code Language Models: How Far Are We?", ICSE 2025 (DOI 10.1109/ICSE55347.2025.00038). Guides label quality, deduplication, realistic splits and evaluation. Code and data: PrimeVul.
  • Supporting paper: Walischewski, Zizzo, Webster, "SIVA: Self Improving Vulnerability Agent" (NeurIPS 2025 workshop). Used for motivation only. Its synthetic examples are not reproduced, because this project uses no AI-generated data.
  • BigVul (2020): "A C/C++ Code Vulnerability Dataset with Code Changes and CVE Summaries". Main training data.
  • CVEfixes (2021, release v1.0.8): "CVEfixes: Automated Collection of Vulnerabilities and Their Fixes from Open-Source Software". Outside test data only.
  • Check the licence in each official repository and keep the attribution in the report.

Known limitations

  • BigVul has a whitespace shortcut: 56.1% of vulnerable but only 1.9% of safe training functions have trailing whitespace. The final CodeBERT model was retrained on normalised code, so normalisation is mandatory at inference.
  • The tool checks one C/C++ function at a time. It does not scan whole repositories, generate exploits or repair code.
  • Rule matches are text-based heuristics, not a full parser. A match is not proof of a vulnerability.
  • Not flagged never means secure.
